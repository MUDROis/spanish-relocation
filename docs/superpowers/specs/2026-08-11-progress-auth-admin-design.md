# Дизайн: сохранение прогресса, вход по email и админ-панель

Дата: 2026-08-11
Проект: spanish-relocation (Интерактивная школа МУДРО)

## Контекст

Статический сайт на GitHub Pages (репозиторий `MUDROis/spanish-relocation`). Без сборки и фреймворков. Две аудитории:

- `index.html` — программа для родителей (20 недель, 60 уроков, карта маршрута в `PHASES`).
- `kids.html` — программа для детей (7 станций, карта-маршрут, альбом наклеек).

Уроки — отдельные HTML-файлы в `lessons/parents/` и `lessons/kids/` (пока по одному: `w01-l1.html`).

Сейчас прогресс хранится только в `localStorage` (наклейки детей `spain_stickers`). Самопроверка «светофор» в уроке родителей не сохраняется нигде. Firebase-проект `spanish-relocation` существует, вход по email/password уже включён.

## Цели

1. Сохранение прогресса учеников в Firestore (поурочно, с датами и лентой активности).
2. Доступ учеников к урокам по email+пароль (аккаунты создаёт только админ).
3. Главные страницы `index.html` и `kids.html` остаются открытыми для гостей.
4. Админ-панель: прогресс каждого ученика (как прошёл урок, самопроверка), управление учениками (добавление, приостановка, смена пароля, удаление).

## Решения (подтверждены пользователем)

- Аккаунты учеников создаёт **только админ**.
- За логином — **уроки**; карты курса открыты гостям.
- Прогресс: самопроверка «светофор» (родители) + детская самопроверка смайликами (дети), наклейки детей, активность и даты.
- Админ — **отдельный аккаунт**, роль определяется полем `role` в `students/{uid}`.
- **Только клиентский SDK**, без Cloud Functions. Поэтому: смена пароля — письмо-сброс (`sendPasswordResetEmail`), удаление — блокировка + удаление данных прогресса (Auth-аккаунт остаётся, доступа без документа нет).
- Сайт остаётся на GitHub Pages; Firebase используется как сервисы (Auth + Firestore).
- Правила Firestore загружаются через **Firebase CLI** (`firebase deploy --only firestore:rules`).

## Не-цели

- Самостоятельная регистрация учеников.
- Полноценное удаление Auth-аккаунтов и смена чужого пароля без участия ученика (требует Admin SDK).
- Защита от умышленного обхода клиентского гейта уроков (на данном масштабе приемлемо).

Всё остаётся статикой на GitHub Pages. Добавляются файлы:

Изменения в существующих файлах:

## Модель данных Firestore

```
students/{uid}                        // профиль
  email: string
  name: string
  createdAt: timestamp
  role: 'student' | 'admin'
  suspended: boolean
  audience: 'parents' | 'kids'

progress/{uid}/lessons/{lessonId}     // прогресс по уроку
  openedAt: timestamp
  completedAt: timestamp | null
  selfCheck: { rowKey: 'green' | 'yellow' | 'red' }   // родители
             { rowKey: 'great' | 'ok' | 'hard' }      // дети (смайлы)
  lastActivity: timestamp

progress/{uid}/stickers               // наклейки детей (объект-мап)
  s1..s7: boolean

progress/{uid}/activity/{eventId}     // лента событий
  type: 'lessonOpened' | 'lessonCompleted' | 'selfCheck' | 'sticker'
  ts: timestamp
  lessonId?: string
```

Соглашение об идентификаторе урока: `parents-w01-l1`, `kids-w01-l1` (префикс программы + неделя + номер).

Данные наклеек: при входе ребёнка `localStorage` (`spain_stickers`) переносится в `progress/{uid}/stickers` (если там пусто), далее читается из Firestore.

## Security Rules (`firestore.rules`)

- `students/{uid}`: чтение — себе и админам; создание — только админом (проверка `get(students/{request.auth.uid}).data.role == 'admin'`), при создании роль всегда `student`.
- Bootstrap админа: если `students/{uid}` отсутствует, а email пользователя в списке админов (жёстко прописан в правилах) — разрешено создать себе документ с `role: 'admin'`.
- `progress/{userId}/{docId}`: чтение/запись — если `userId == request.auth.uid` (владелец) либо вызывающий — админ.
- Роль `admin` нельзя установить через обычный клиент: правила проверяют соответствие email списку.

## Потоки

### Вход (`login.html`)

- Форма email+пароль; ошибки по-русски.
- Ссылка «Забыли пароль?» → `sendPasswordResetEmail`.
- После входа: если `students/{uid}` нет — bootstrap (админ по списку email или новый ученик с ролью `student`).
- Возврат на страницу-источник через параметр `?next=`.

### Гейт уроков (`lesson-gate.js`)

- Нет сессии → редирект на `login.html?next=<урок>`.
- `students/{uid}.suspended == true` → блокирующий экран «Доступ приостановлен».
- Вход есть → контент открыт, пишутся события:
  - первое открытие → `openedAt` + событие `lessonOpened`;
  - нажатия самопроверки → `selfCheck` + событие `selfCheck`;
  - кнопка «Урок завершён» → `completedAt` + событие `lessonCompleted` + конфетти.

### Админ-панель (`admin.html`)

- Доступ только при `role == 'admin'`.
- Список учеников: имя, email, программа, статус (активен/приостановлен), пройдено уроков, последняя активность, кнопки.
- Добавление ученика: имя, email, пароль, программа → `createUserWithEmailAndPassword` + создание `students/{uid}`.
- Приостановить/возобновить: переключение `suspended`.
- Сменить пароль: `sendPasswordResetEmail(email)` — письмо ученику.
- Удалить: удаление `students/{uid}` и `progress/{uid}` (аккаунт Auth остаётся, доступ автоматически закрыт — документ отсутствует).
- Карточка ученика: поурочный прогресс с детализацией самопроверки (🟢/🟡/🔴 или 😀/😐/😖 по каждому навыку), даты, лента активности.

## Настройка (разово, пользователь + CLI)

1. Firebase-проект `spanish-relocation`: Authentication → Email/Password (уже включён), создать Firestore.
2. В консоли Auth → Settings → Authorized domains добавить `MUDROis.github.io`.
3. В `firebase-config.js` вписать web config проекта и email админа(ов).
4. В `firestore.rules` вписать те же email админа(ов).
5. Загрузить правила через CLI:
   ```
   firebase login
   firebase use spanish-relocation
   firebase deploy --only firestore:rules
   ```
   Для этого в репозитории есть `firebase.json` и `firestore.rules`.

## Тестирование

Тестового фреймворка в проекте нет. Проверка вручную (локально через простой сервер, например `npx serve`):

1. Гость открывает `index.html` и `kids.html` — карты видны, кнопка «Войти».
2. Гость открывает урок — редирект на `login.html`.
3. Ученик входит, открывает урок, жмёт «светофор»/смайлики, «Урок завершён» — данные появляются в Firestore.
4. Ребёнок собирает наклейку на `kids.html` — она сохраняется в аккаунте и переживает смену браузера.
5. Админ входит, видит прогресс ученика, добавляет/приостанавливает/сбрасывает пароль/удаляет ученика.
6. Приостановленный ученик при попытке открыть урок видит блокирующий экран.

## Ограничения (осознанные)

- Смена пароля — через письмо-сброс, ученик сам задаёт новый пароль.
- Удаление ученика не удаляет Auth-аккаунт (без Admin SDK невозможно), но полностью закрывает доступ и убирает все данные.
- Гейт уроков клиентский: защита достаточна для «честных» пользователей, но не от умышленного обхода.
